# 음악 → 색채 변환기 (Music to Color)

음악 파일의 주파수를 분해해서 **가시광선 색**으로 바꿔 보여주는 브라우저 시각화 도구입니다.
소리는 한 가지 음만 나지 않으므로(화음·여러 악기) 여러 주파수대를 동시에 여러 색으로
보여주고, 그 색이 매 프레임 제멋대로 왔다갔다 하지 않도록 **격자 칸마다 주파수대를
미리 고정**해 둡니다. 소리가 커지면 그 칸이 밝아지고, 작아지면 어두워질 뿐 위치는
흔들리지 않습니다.

## 바로 쓰기

`index.html`을 브라우저로 열고(서버 불필요, 외부 전송 없음) 음악 파일을 올리면 재생과
동시에 색이 채워집니다. 우측 상단 **⛶ 전체화면** 버튼으로 화면을 최대화할 수 있고,
**⚙ 설정** 버튼으로 패널을 접었다 펼 수 있습니다. 창 크기·전체화면 전환 시 항상
컨테이너에 맞는 가장 큰 크기로 다시 배치됩니다(격자형은 가로세로 비율대로, 방사형·
사이클·관계형은 정사각형, 직선형은 컨테이너 전체).

파일이 없어도 **샘플 음원** 패널의 버튼 4개(주파수 스윕·아르페지오·리듬 비트·지속 화음)로
바로 재생해 볼 수 있습니다. 모두 저작권 걱정 없는 합성 사인파로, `python -m
music_to_color.make_samples`(아래 Python 섹션)로 `samples/`에 다시 만들 수 있습니다.

## 사용자가 직접 설정하는 것

| 설정 | 의미 | 기본값 |
|---|---|---|
| 소리 주파수 구간 | 가청 20~20,000Hz 중 실제로 색으로 바꿀 구간 | 100~4,000Hz |
| 가시광선 주파수 구간 | 매핑될 빛의 주파수(THz) 구간 | 405~790THz (가시광선 전체) |
| 연결 방식 | 두 구간을 잇는 곡선 모양: 리니어 / 로그 / 지수 | 로그 |
| **시각화 방식** | 격자형(음계) / 격자형(주파수) / 방사형 / 사이클 / 관계형 / 직선형 / **채색 악보** — 아래 "시각화 방식 일곱 가지" 참고 | 격자형(음계) |
| 해상도 (격자-주파수·방사형·직선형·채색 악보일 때만) | 밴드 개수 또는 줄 수(모드별로 범위가 다름) | 모드마다 다름 |
| 부드러움 | 프레임 간 밝기 평활(떨림 완화) | 0.7 |
| **배음 억제** | 기음(가장 강한 실제 음)만 밝게 남기고 배음은 어둡게 깎는 강도 | 0.7 |
| 최소 밝기 | 무음일 때도 패턴이 희미하게 보이는 정도 | 0.08 |
| 칸 선명하게 (격자형일 때만) | 칸 경계를 또렷하게/부드럽게 | 선명하게 |

**연결 방식**이 로그일수록 사람의 음정 체감(옥타브=배수)에 가깝게 저음 구간이
넓게, 고음 구간이 좁게 색이 퍼집니다. 지수는 반대로 저음을 압축하고 고음을 넓힙니다.

## 동작 원리

### 시각화 방식 일곱 가지

밴드(칸·점·막대 하나하나)마다 같은 비율 위치(t)의 가시광선 주파수로 매핑되어
**고정 RGB**를 가지며, 이 고정 색 배치는 설정이 바뀔 때만 다시 계산됩니다. 여섯
방식은 이 밴드들을 화면에 "어디에" 놓을지만 다릅니다.

- **격자형(음계, 기본).** 가로는 왼쪽부터 도·도#·레·레#·미·파·파#·솔·솔#·라·라#·시
  반음 12칸, 세로는 소리 주파수 구간이 담는 옥타브 수만큼 쌓입니다. 높은 옥타브가
  위로 가도록 배치해서, 음이 높아지면 격자에서도 위로 올라갑니다. 칸 하나 = 평균율로
  고정된 특정 음(예: "라4") 하나의 주파수이고, 실제 소리가 그 음 정확히가 아니어도
  가장 가까운 반음 칸에 반영됩니다(온음계 7음 사이의 반음까지 전부 표현).
- **격자형(주파수).** 격자가 N×N이면 소리 주파수 구간을 N² 개 밴드로 균등(연결
  방식에 따라 리니어/로그/지수)하게 쪼갭니다. 음 이름에 매이지 않고 연속적인
  스펙트럼을 더 세밀하게 보고 싶을 때 씁니다.
- **방사형.** 연속 스펙트럼 밴드를 원 한 바퀴(저음부터 고음까지 시계방향)에
  펼쳐두고, 소리가 커지면 그 방향으로 반지름이 늘어납니다 — 클래식한 원형 스펙트럼
  애널라이저.
- **사이클.** 음이름 12개를 5도권(circle of fifths) 순서로 원 둘레에 고정합니다.
  이웃한 음끼리 5도 관계라서, 조성이 있는 음악은 특정 구역에 밝은 점이 몰립니다.
- **관계형.** 같은 12개 노드를 반음 순서로 배치하고, **동시에 울리는 음끼리 선으로
  이어** 화음의 모양을 그려 보여줍니다.
- **직선형.** 저음에서 고음까지 왼쪽에서 오른쪽으로, 클래식 이퀄라이저 막대
  그래프입니다.
- **채색 악보.** 나머지 여섯과는 성격이 다릅니다 — 지금 재생 중인 순간이 아니라
  **곡 전체**를 한 번에 분석해 고정된 색면 하나로 보여줍니다. 음악은 시간이 지나야
  들리지만, 악보는 그걸 한 장에 고정해 기호로 적어둔 것이죠. 악보는 명확하지만
  예술적이기는 어렵습니다. 이 모드는 같은 "시간을 한 장에 고정"하는 일을 색으로
  합니다. 자세한 동작은 아래 "채색 악보: 곡 하나를 한 장의 색면으로" 참고.

### 기음은 밝게, 배음은 어둡게

사인파가 아닌 실제 악기 소리는 기음(기본주파수) 하나에 배음(정수배 倍音)이 줄줄이
따라붙고, 배음도 꽤 크게 잡혀서 그대로 보여주면 한 음을 쳐도 여러 대역이 동시에
번쩍입니다. 매 프레임 스펙트럼에서 피크를 모두 찾아 **가장 강한 피크부터** 훑으면서,
이미 인정된 기음의 정수배 주파수(2~16배, 3% 오차 이내)에 걸리는 약한 피크는 "배음"으로
분류해 그 주변만 어둡게 깎습니다. 정수배로 안 걸리는 강한 피크는 새로운 기음(동시에
울리는 다른 음)으로 인정해 그대로 밝게 둡니다. "배음 억제" 슬라이더로 깎는 세기를
조절합니다(0=보정 없음, 1=강하게). 220Hz 톱니파로 검증: 억제 0일 때 기음+배음
7개 대역이 모두 0.5 이상으로 밝았지만, 억제 0.9에서는 기음(220Hz) 하나만 0.5를
넘고 나머지 배음은 모두 절반 이하로 어두워집니다.

### 실시간 분석 · 렌더링

Web Audio API `AnalyserNode`로 FFT를 돌리고, 매 프레임 위 보정을 거친 스펙트럼에서
각 밴드의 고정 주파수 지점을 가장 가까운 두 FFT bin으로 선형보간해 밝기(0~1)를
구합니다. 밴드 수가 FFT 해상도보다 훨씬 많아도(격자형-주파수 최대 1,000,000칸) 빈
칸 없이 매끈합니다. 격자형 두 가지는 cols×rows 픽셀짜리 오프스크린 캔버스에 색을
채운 뒤 화면 캔버스로 확대해 그리고, 방사형·사이클·관계형·직선형은 화면 캔버스에
원·선·막대를 직접 그립니다. 색 자체는 가시광선 주파수(THz)를 파장(nm)으로 바꾼 뒤
표준 근사식(Dan Bruton 알고리즘)으로 RGB를 계산합니다.

### 재생 버튼이 처음엔 반응 없던 문제

브라우저는 자동재생을 막으려고 `AudioContext`를 사용자 제스처(클릭) **안에서 직접**
풀어줘야만 소리를 냅니다. 파일을 올리거나 샘플을 고르는 동안 `await`로 디코딩을
기다리면 그 사이에 "방금 클릭했다"는 유효기간이 끊겨서, 재생 버튼을 눌러도 반응이
없고 그다음 클릭(새 제스처)에서야 풀리는 문제가 있었습니다. 이제 파일 선택·샘플
버튼·재생 버튼 각각의 클릭 핸들러 맨 처음, `await` 전에 `AudioContext.resume()`을
동기적으로 바로 호출해서 첫 클릭부터 바로 재생됩니다.

### 채색 악보: 곡 하나를 한 장의 색면으로

화면을 **일정한 두께의 가로줄 N개**로 나눕니다("줄 수" 설정). 줄 하나는 곡의 한
구간(시간)을 맡고, 그 구간 안에서 왼쪽에서 오른쪽으로 시간이 흐르며, 구간의
**두께 안에는 그 순간의 주파수 스펙트럼이 저음(아래)부터 고음(위)까지 색으로
쌓여** 있습니다. 한 줄이 끝나면(오른쪽 끝에 닿으면) 바로 아래 다음 줄의 왼쪽
끝에서 이어집니다 — 책을 읽듯 왼쪽 위에서 오른쪽 아래로 줄바꿈하며 곡 전체를
한 장에 담습니다.

이걸 만들려면 "지금 재생 중인 소리"가 아니라 **파일 전체**가 필요합니다. 그래서
`OfflineAudioContext`로 곡 전체를 실시간보다 빠르게 다시 렌더링하면서, 줄 수 x
140(가로 칸 수) = 전체 구간 수만큼 정해둔 시점마다 렌더링을 잠깐 멈추고
(`suspend`/`resume`) 그 순간의 스펙트럼을 분석기로 읽습니다. 각 구간에
기음/배음 보정과 bin 보간을 거쳐 밝기를 구하고, 접은 격자 위에 채워 넣습니다.
한 번 분석하면 끝 — 그다음은 재생해도 그림이 바뀌지 않는 고정된 "초상"입니다.
재생 중에는 지금 위치에 해당하는 칸에 흰 테두리로 커서를 그려서, 고정된 그림
위에서 곡을 따라가며 들을 수 있게 했습니다.

줄 수는 설정에서 바꿀 수 있고(4~40), 소리/빛 구간·연결 방식·배음 억제를 바꾸면
전체를 다시 분석합니다(곡이 길면 잠깐 걸립니다 — "분석 중..."이 뜹니다). 가로
칸 수(140)와 줄 하나의 주파수 세로 칸 수(30)는 지금은 고정값입니다.

## 파일 구성

```
index.html, css/style.css          — 단일 화면 UI (패널 설정, 캔버스, 전체화면)
js/colorModel.js                   — 주파수 ↔ 색채 매핑 수학 (스케일, 4종 밴드 목록, 파장→RGB)
js/audioEngine.js                  — Web Audio 재생(제스처 unlock 포함) + FFT → 기음 강조 → 밴드별 밝기,
                                      OfflineAudioContext로 곡 전체를 분석하는 analyzeBuffer()도 여기
js/visualizer.js                   — 격자/방사형/사이클/관계형/직선형 캔버스 렌더러(리사이즈/전체화면 대응)
js/app.js                          — UI 연결, 메인 루프, 채색 악보 모드의 비동기 재분석

python/music_to_color/color_model.py  — js/colorModel.js 와 동일한 매핑 수학(Python)
python/music_to_color/audio_render.py — WAV 오프라인 분석 CLI (기음 강조 포함, JSON/영상 출력)
python/music_to_color/make_samples.py — index.html의 샘플 재생용 합성 WAV 4개 생성
python/tests/test_color_model.py      — 매핑 수학 단위 테스트
samples/                              — 합성 샘플 음원 (sweep/arpeggio/rhythm_beat/sustained_chord)
```

JS와 Python은 같은 수학(스케일 정규화, 파장→RGB, 밴드 생성)을 각자 구현하며,
위 예시로 두 쪽 결과가 일치함을 확인했습니다(밴드[0]: 100.72Hz → 405.75THz →
RGB(183,0,0), 양쪽 동일).

### Python CLI (선택 — 오프라인 분석/미리보기 영상)

브라우저 없이 WAV 파일을 분석해 프레임별 밴드 밝기를 JSON으로 뽑거나, `imageio`가
설치돼 있으면 미리보기 영상도 만들 수 있습니다.

```bash
cd python
pip install -r requirements.txt   # numpy
pip install -e .                  # music_to_color 패키지 설치(테스트/CLI용)

python -m music_to_color.audio_render \
  --input song.wav --output-json frames.json \
  --layout chroma --sound-min 100 --sound-max 4000 --scale log --harmonic-suppress 0.7

# 영상까지 원하면: pip install imageio imageio-ffmpeg 후
python -m music_to_color.audio_render --input song.wav --output-video preview.mp4 ...

pytest tests/   # 매핑 수학 단위 테스트
```

## 주의

**격자형(주파수)** 해상도를 500×500(25만 칸) 이상으로 올리면 기기에 따라 느려질 수
있습니다(화면에 경고가 뜹니다). 대부분의 음악은 32×32~128×128 정도에서 이미
충분히 풍부하게 보입니다. 방사형/직선형은 애초에 해상도 상한이 낮아(각 360/200)
느려질 일이 거의 없습니다.
