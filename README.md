# 보조사업 부정수급 가능성 목록

보조금통합포털 **정보공시(개별 보조사업 정산 내역)** 를 수집해 **부정수급 요건 모델**로 평가하고,
사업별 **부정 가능성(%)** 을 이유·근거 법령과 함께 내림차순으로 목록화하는 도구입니다.

## 부정수급 요건 모델

보조금법·공공재정환수법의 **법적 구성요건 5축**으로 공시 집행내역의 정량 신호를 묶습니다.

| 축 | 요건 | 근거 법령 | 대표 신호 |
|----|------|-----------|-----------|
| A | 허위청구 | 보조금법 §40 · 공공재정환수법 §2① (제재부가금 500%) | 자기거래(사업자번호·대표자 일치), 중복 결제, 단일거래 고액 거래처, 주말 집행, 벤포드 이탈 |
| B | 과다청구 | 공공재정환수법 §2② (300%) | 라운드넘버 편중, 동일금액 반복, 집행률 초과 |
| C | 목적 외 사용 | 보조금법 §22·§41 · §2③ (200%) | 인건비 과다, 사업 종료 직전 몰아쓰기 |
| D | 경쟁 회피·유착 | 보조금법 시행령 계약규정 | 쪼개기 계약(한도 회피), 몰아주기(HHI), 수의계약 과다 |
| E | 정산 신뢰성 훼손 | 보조금법 §27(정산보고) | 음수·취소, 증빙 미기재, 잔액 0원 정산 맞추기 |

**부정 가능성 %** = Σ(요건축 가중치 × 축별 점수) × 스케일 × 표본 신뢰도.
축별 점수는 같은 축의 신호가 겹칠수록 보수적으로 확신이 증가합니다.
각 사업 카드에 **축별 막대 + 사람이 읽는 이유 목록 + 해당 요건의 근거 법령 + 신고서 초안**을 제공합니다.

**검증**: 자기거래·쪼개기를 심은 사업 74% vs 로그정규 분포의 정상 사업 20~27%로 분리(Python·JS 동일).

## 데이터를 넣는 두 가지 방법

### 1) 포털 공시 파일 직접 분석 (권장 — 지금 바로 됨)

`index.html`을 열고 **공시 엑셀/CSV**를 올리면 브라우저 안에서 즉시 순위가 나옵니다(외부 전송 없음).

1. [보조사업자 정보공시](https://www.bojo.go.kr/ea/getEA001201View.do)에서 회계연도 조회
2. **파일 저장**으로 목록/집행내역을 엑셀로 내려받기
3. 앱에 올리기 → 사업별 부정 가능성 % 목록

CSV는 라이브러리 없이 처리하고, XLSX는 SheetJS(cdnjs)로 읽습니다.

### 2) 자동 수집 — 공공데이터포털 OpenAPI (권장 자동화 경로)

`bojo.go.kr` 공시 **웹 검색**은 자동 대량 수집이 **의도적으로 차단**돼 있습니다(아래 조사 결과).
그래서 자동화는 정부가 대량 조회용으로 공식 제공하는 **공공데이터포털 OpenAPI**를 정규 경로로 씁니다.

1. [기획재정부_국고보조금 정보](https://www.data.go.kr/data/15097584/openapi.do)에서 **활용신청(무료)** → 서비스키 발급
2. 저장소 **Settings → Secrets and variables → Actions** 에 `DATA_GO_KR_KEY` 로 추가
3. **Actions → 정보공시 수집·분석 → Run workflow → mode: `openapi`**
4. 수집 결과가 `data/analysis.json`으로 커밋되고, 앱이 자동으로 % 목록을 그립니다(최초 1회면 충분)

```
crawler/collect_openapi.py — data.go.kr OpenAPI 페이지네이션 수집 → 요건 모델 분석
.github/workflows/collect.yml — mode: openapi (DATA_GO_KR_KEY 시크릿 사용)
```

### bojo.go.kr 공시 웹 검색 자동화 — 조사 결과(정직한 고지)

공시 검색 페이지를 헤드리스 브라우저로 28회에 걸쳐 정밀 분석한 결과, **다음 세 겹의 차단**으로
프로그램 자동 수집이 성립하지 않음을 확인했습니다. 이건 이 도구의 한계가 아니라 포털의 설계입니다.

1. **실제 데이터 API 확인** — 검색은 `POST /ea/retrieveInfoPblntfTrgetMngList.do`(JSON, CSRF 없음)로
   동작함을 f_search 소스에서 확정했습니다.
2. **서버 조회상한** — 이 API에 프로그램으로 질의하면 조건(연도·시도·시군구·사업자구분·공시일 구간)을
   아무리 좁혀도 일괄 `"조회 범위를 초과하였습니다"`로 거부됩니다. 광주 사회복지시설 한 건까지 동일.
3. **커스텀 위젯 + name 없는 폼** — 관서·자치단체 선택기가 `<select>`가 아닌 커스텀 JS 위젯이라
   헤드리스에서 코드 목록이 로드되지 않고, 검색 폼 필드도 프로그램 직렬화가 되지 않습니다.

→ 결론: **공시 웹 검색의 무인 자동 수집은 포털이 막고 있어**, 자동화는 위의 **OpenAPI**로,
즉시 사용은 **(1) 포털에서 파일을 받아 올리는 방식**으로 합니다. 실제 사람이 브라우저에서
연도 조회 후 **파일 저장**(엑셀)은 정상 동작하므로 데이터 확보 자체에는 문제가 없습니다.
정찰 산출물은 `data/recon-browser/`(스크린샷·DOM·함수 소스·응답 로그)에 남겨 두었습니다.

### 안전장치(수집기)

호스트 허용목록 · robots.txt 준수 · 요청 간 지연 · 식별 가능한 User-Agent · 페이지/행 상한 ·
Actions 시간 예산 내 커서 이어받기.

## 파일 구성

- `index.html` — % 목록 단일 화면(필터·검색·정렬, 사업별 이유·근거법령·신고서 초안), 공시 파일 업로드 분석
- `model.js` — 요건 모델(브라우저판) · `crawler/model.py` — 요건 모델(수집 파이프라인판, 동일 로직)
- `crawler/browse.py` — Playwright 공시 크롤러(recon/collect/download) · `crawler/collect.py` — requests 기반 정적 표 수집
- `.github/workflows/collect.yml` — 수집·분석 워크플로

## 주의

이 목록의 **%는 공시 내역의 통계적 이상 징후 수준이며 부정수급의 확정이 아닙니다.**
각 이유는 확인해야 할 조사 단서이며, 최종 판단은 조사·수사기관의 권한입니다.
허위 사실의 신고·유포는 무고·명예훼손 책임이 따를 수 있습니다. 신고 접수: 청렴포털 clean.go.kr · 국번 없이 110/1398.
